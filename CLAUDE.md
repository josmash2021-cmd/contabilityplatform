## The product
Spanish-first (also English) accounting SaaS for Hispanic small businesses and personal finances in the US.
Live: https://aethelaccountingplatform.com · repo folder `contabilityplatform` · Railway deploys `main`.
- Two modes per account: **business** (sales/POS, invoices, quotes, customers, vendors, expenses, receipts, bank, reports, accountant, team, assistant, taxes) and **personal** (bank, transactions, budgets, goals, subscriptions, assistant, taxes).
- Plans: business Básico / Pro / Negocio, personal Básico (free) / Pro; 7-day free trial, no card. Rules live in `contracts/planFeatures.ts` (single source); prices in `src/components/marketing/content.ts` must match `api/lib/plans.ts`.
- Tax prep is **free** for the client, **Alabama only**, documents encrypted in the DB (`TAX_FILES_KEY`).
- Public site: `/` (landing when signed out), `/producto`, `/como-funciona`, `/seguridad`, `/precios`, `/preguntas`, `/privacy`, `/terminos` (= `/terms`, tax service terms) and `/terminos-de-uso` (= `/terms-of-use`, the app's own terms, `src/i18n/copy/termsOfUse.ts`); both are drafts the owner should have a lawyer review. Their public contact address (and the Privacy Policy's) is `CONTACT_EMAIL` in `contracts/constants.ts` (team@personalandbusinesssolution.com; an address can't have "&" after the @). The owner's own admin login (`OWNER_EMAIL` in `api/auth-router.ts`) is a different thing: never change it. The legal pages' back arrow uses `useBack()` (`src/hooks/useBack.ts`): opened on their own it goes home. Sign-in: `/login`, `/register`, `/forgot-password`, `/join`.
- Admin (role `admin`): its own shell `src/components/layout/AdminLayout.tsx` (menu Resumen, Usuarios, Pagos, Impuestos, Soporte, Bloqueados, Sistema + "Volver a mi cuenta"; phones: bottom bar + Más), not the business app's. `/admin` = Resumen (`AdminHome.tsx`: 4 numbers, weekly chart, Para hoy, newest users, activity), `/admin/usuarios` and `/admin/bloqueados` (`AdminUsers.tsx`, filters `?estado=trial|paying|failed|canceled|free`, `?q=`), the person's card `AdminUserSheet` (payments, banks, team, taxes; Escribirle, Dar más días gratis, Regalar acceso, Cambiar a Personal/Negocio (`admin.setMode`: the only way to change an account's type, chosen at sign-up; nothing is deleted; blocked for admins and, to Personal, for team members or owners with a team; the person signs out and in again), Bloquear, Borrar), `/admin/sistema` (`AdminSystem.tsx`: services + maintenance), and the older pages inside the same shell: `/admin/ingresos|suscripciones` (AdminDetail), `/admin/impuestos`, `/admin/soporte`, `/admin/actividad/:id`. Every number comes from ONE rule per person, `userStatus` in `api/lib/adminOverview.ts` (admin, blocked, trial, paying, gift = `ADMIN_GRANT_` access (not income), failed, canceled, free, ended) so counts add up; `admin.overview` / `admin.userDetail` / `admin.extendTrial` in `api/admin-router.ts`; Alabama days/weeks (Monday). More free days: `trialExtensions` table (`api/lib/trialExtensions.ts`), read by `getTrialInfo(createdAt, now, until)` in `getPlanContext` and `subscription.status`. Words: `src/i18n/copy/admin.ts`. Check with `browser/cdp-admin-body.mjs` on a clean local DB (`bash pbs-dev/admin-fresh.sh`, server on :3458 with `DATABASE_URL=…/pbsadmin`; 27 checks: the numbers by hand, the card, phone width).

## Owner's standing rules (always)
- Talk to the owner, write step descriptions and commit messages **in Spanish**. Code comments stay in English.
- **Show before publishing** (owner's rule since 2026-11-23): after verified work on the local server, show real screenshots (an artifact page, phone and computer) and wait for the owner's OK. Then commit and push to **both** `origin feat/funciones-planes` and `origin feat/funciones-planes:main`, wait for the Railway deploy (`railway deployment list --json`) and check `https://aethelaccountingplatform.com/api/health`.
- **Ask first** before touching production data. Never `drizzle-kit push`/recreate against production. `TAX_FILES_KEY` must never change. Never paste secrets.
- Production's database can't be reached from here: the app uses the internal `MYSQL_URL`; the public `DATABASE_URL` proxy closes the connection, and going into the server (`railway ssh`) is blocked unless the owner allows it. Account changes go through the admin (e.g. Cambiar a Personal/Negocio in the person's card).
- Design must look **modern and current** (soft shadows, rounded shapes, eased motion, modern cursors/icons). Nothing dated.
- Copy: no « » or similar marks; no government logos/seals (IRS, Alabama); bank/merchant logos are real modern PNGs in `public/brands/`; Excel/PDF logos via `src/components/FileLogo.tsx`.
- Public site and sign-in pages block zoom (`src/hooks/useNoZoom.ts`); the app allows zoom.

## Patterns to follow
- **Words**: every UI string in `src/i18n/copy/*.ts` as `{ es, en }` (type = `typeof es`), read with `useCopy(dict)`; server messages via `msg(lang, key)` in `api/lib/i18n.ts`; language comes in the `x-lang` header.
- **Language is automatic** (owner's choice, 2026-11-23): Spanish when the phone/computer is in Spanish (`navigator.languages`), English otherwise (`src/i18n/lang.ts`). There is NO ES/EN switch on the site or sign-in pages (`LanguageSwitcher` was deleted); only Perfil > Idioma inside the app (`Sections.tsx` → `setLang`) overrides it, saved under `localStorage "lang_pref"` (the old switch's `"lang"` key is ignored on purpose). Tests set `lang_pref`; check with `browser/cdp-autolang-body.mjs` (38 checks: es/en devices, every page, phone menu).
- **New tables**: created on first use with `CREATE TABLE IF NOT EXISTS … ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` inside an `ensure…Tables(db)` promise, queried with raw `db.execute(sql…)`. Raw rows: use `rowsOf()`; times come back as `"YYYY-MM-DD HH:MM:SS"` text in UTC, convert with `utcDate()` (`api/lib/support.ts`) before sending to the browser. When an account is deleted (`api/admin-router.ts` deleteUser) its rows must go: add the table to `USER_TABLES` (`api/lib/userDataCleanup.ts`) or a `deleteUser…Data` call.
- **Claude**: model `claude-opus-5-5`, `output_config: { effort: "low" }` for chat answers. In-app assistant: `api/assistant-router.ts` + tools in `api/lib/assistantTools.ts` (Alabama/Central day boundaries via `salesWindow`). Site support chat: `api/support-router.ts` + `api/lib/support.ts` (knowledge = the /preguntas FAQ with real prices).
- **Email**: `api/lib/mailer.ts` (`sendMail` never throws, `brandedHtml`, `mailP`, `mailNote`…), Gmail SMTP via `SMTP_USER`/`SMTP_PASS`; email images must be PNG (Gmail drops SVG).
- **React lint**: hooks before any early return; no synchronous `setState` inside effects (do it in callbacks/timers); `react-refresh/only-export-components`; class names with `cn` from `@/lib/utils`.
- **Phone tab bar** (`AppLayout` `nav[data-tabbar]`, 16px under the labels): the Assistant's dock (`pb-[88px]`), the POS bar (`bottom-[86px]`) and `--toast-bottom` in index.css sit on top of it; move them together.
- **Installed on the home screen** (standalone): `src/main.tsx` adds `viewport-fit=cover` so `env(safe-area-inset-*)` works (`useNoZoom` keeps it); bottom spacing uses `max(16px, calc(env(safe-area-inset-bottom) + 8px))`. Test with `navigator.standalone` set before load (`browser/cdp-fix3-body.mjs`).
- **Phone "+"**: opens the Crear sheet (`newItems` in `src/i18n/copy/app.ts`, icons in `newIcon` in AppLayout); computers keep the "+ Nuevo" dropdown.
- **Home page tour** (`DashboardTour`): starts by connecting the bank (ConnectView), then Banco, Inicio, Ventas, Clientes, Gastos, Reportes. The pointer is a guide point on a curve followed by a soft spring that tracks the target element live (so clicks land on it); clamp the move's progress to 0..1 (a negative power is NaN and freezes it). Check with `browser/cdp-tourbank-body.mjs` (speed per frame) and `browser/cdp-fix3-body.mjs` (every click on its target).
- **Changing page in the app**: one persistent wrapper `.page-fx` in `AppLayout` (data-fx out/in, layout effect on the location) goes soft, swaps and eases back to sharp with no sharp frame in between; at rest it has no filter. Measure with `browser/cdp-pagefx-body.mjs` (phone, CPU x4, filter per frame).
- **Never a blank page** (owner saw /como-funciona blank right after a deploy: a tab from the old version asked for a code file that no longer existed, while Railway was switching versions): `src/lib/newVersion.ts` reloads once (15 s guard) on a missing-code error (lazyPage in App.tsx and the `vite:preloadError` listener in main.tsx); if it already did, the `ErrorBoundary` around all routes (App.tsx, `resetKey` = the address) shows "Esta página no cargó bien" with Recargar / Ir al inicio (`src/i18n/copy/appError.ts`). The server (`api/lib/vite.ts`) sends HTML with `Cache-Control: no-cache` and `assets/` files `immutable` (an open tab keeps the pieces it already has, and with the idle preload that's all of them). Check with `browser/cdp-stale-body.mjs` (code missing once / every time, the headers).
- **The menu must react at once** (owner: "tarda en cargar o reaccionar"): `go()` navigates immediately (no waiting for the blur; `startTransition` keeps the old page soft while a page's code still downloads), the tapped item is selected before the page changes (`pend` → `navPath`), and every page's code is warmed up when the app is idle (`lazyPage(load, "app" | "admin")` in App.tsx → `src/lib/preloadPages.ts`, `preloadWhenIdle` in AppLayout/AdminLayout; skipped with Save-Data). Blur: 180 ms out, 420 ms back. Measure with `browser/cdp-navspeed-body.mjs <out> <chrome> biz|per` (every menu item, normal connection: selected ≤ 100 ms, content ≤ 700 ms first visit / ≤ 350 ms after; now ~6 ms, ~45 ms, ~30 ms).
- **Sign-in screens** (`AuthLayout`): light side panel (computers only) with `AuthShowcase` (the REAL app: screenshots of demo accounts in `public/auth-showcase/<es|en>/<scene>-<pc|tel>.webp`, in a browser window + phone, straight, changing by "fade through" every 4.6 s, sized to the space by a ResizeObserver; business: home, bank, reports, taxes; personal: home, budgets, goals, taxes. The signature page says who checked which ID. "En papel": the client downloads the 8879, signs by hand and uploads a photo (`tax.upload` kind `f8879_paper`, only at step 3); the preparer marking it OK (`adminSetDoc`) sets `approvedAt` (taking it back clears it). Signing from home in the app would need third-party KBA (DocuSeal/DocuSign researched, not used). Joint returns: the spouse isn't handled yet (use paper).
- **Steps and emails**: the 8 steps are moved by the preparer (`adminSetStep`), except Recibida (client's Enviar) and Revisa y firma, which comes by itself when the preparer has uploaded both the 1040 (`final_fed`) and the 8879 (`adminUpload` returns `movedToSign`). Going back sends nothing.
- Tax pages are behind an email-code gate (`api/lib/taxGate.ts`, header `x-tax-unlock`).
